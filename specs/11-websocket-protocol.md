## Overview

Single WS endpoint handles all real-time events. Authentication is via the same `auth_token` cookie. The server-side `ConnectionManager` maintains a registry of all connected tabs per user.

---

## Endpoint

```
ws://host/ws?tab_id=<uuid>
```

- Cookie `auth_token` must be present (validated on upgrade)
- `tab_id` is generated by the client per browser tab (stored in `sessionStorage`)
- If token invalid → close with 4001

## ConnectionManager (`backend/app/core/connection_manager.py`)

```python
class ConnectionManager:
    # user_id → dict[tab_id, WebSocket]
    connections: dict[UUID, dict[str, WebSocket]]

    async def connect(user_id, tab_id, ws): ...
    async def disconnect(user_id, tab_id): ...

    async def send_to_user(user_id, event): ...       # all tabs of a user
    async def send_to_room(room_id, event, exclude=None): ...  # all members
    async def send_to_users(user_ids, event): ...     # targeted multi-user
```

### Room Broadcast

To send to all members of a room:
1. `SELECT user_id FROM room_member WHERE room_id = :room_id`
2. For each `user_id`, call `send_to_user(user_id, event)` if connected

This is acceptable for up to 300 users / 1000-member rooms.

## Connection Lifecycle

```
Client connects
  → Server validates cookie → finds/creates Session
  → Manager.connect(user_id, tab_id, ws)
  → Server sends presence.bulk (friends + room members initial state)
  → Server broadcasts presence.update(user_id, online) to relevant users

Client active → sends presence.heartbeat every 30s
  → Server updates tab_status

Client closes tab
  → Manager.disconnect(user_id, tab_id)
  → Recompute presence for user → broadcast if changed

Server-side keepalive: ping/pong every 30s; close stale connections after 90s
```
